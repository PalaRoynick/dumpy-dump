# Проверка MOD-потенциалов MDcraft

Скрипты сравнивают установленную C++-реализацию с локальными референсными
таблицами и сохраняют CSV, JSON, PNG и общий PDF. Поддержаны `EAMMOD1044`
(по умолчанию), `EAMWMOD1046` и `EAMWMOD0644`.

Параметры потенциалов, референсные данные и настройки кластера не включены.
Нужны Python >= 3.9, numpy, matplotlib и установленный MDcraft с MOD-классами.
Ничего автоматически не устанавливается и не скачивается.

## Подготовка

В этой папке создайте `reference/` с вашими исходными таблицами:

| Файл | Столбцы |
| --- | --- |
| `V_Zha.dat` | r [nm], r·V(r), r·VirX = dV/dr |
| `density_Zha.dat` | r [nm], n(r), r·dn/dr |
| `Femb_Zha.dat` | n, F(n), dF/dn |

Первая строка каждой таблицы — заголовок. Энергии задаются в kJ/mol,
расстояния — в nm. Автоматического пересчёта единиц и подгонки масштаба нет.

Преобразуйте локальный файл параметров вашим существующим `eamReader.py`:

```bash
python export_parameters.py \
  --reader /path/to/eamReader.py \
  --input /path/to/potential.dat \
  --out params-ch.npz
```

Ожидаемый результат `eamReader`: `(rcut, aVr, bVr, rVr, V, W, C, D, F, G)`.
Массивы должны быть одинаковой длины 12..32, включая элементы с индексами 0 и 1.
Коэффициенты не печатаются. NPZ содержит ваши параметры и должен остаться локальным.
Вместо конвертера можно сохранить переменные конструктора самостоятельно:

```python
import numpy as np
np.savez("params-ch.npz", Rcutoff=rcut, aVr=aVr, bVr=bVr, rVr=rVr,
         V=V, W=W, C=C, D=D, F=F, G=G)
```

Также поддержан JSON-словарь с этими десятью ключами.

## Запуск

Используйте Python окружения, в котором установлен MDcraft, без MPI-launcher:

```bash
python compare_mod.py --params params-ch.npz --out results-ch --symlog
```

По умолчанию проверяется именно **r·dn/dr**. Если численные данные плотности
согласуются с невзвешенной производной, аудит отметит это отдельно, но не изменит
трактовку автоматически. Для явного альтернативного сравнения:

```bash
python compare_mod.py --params params-ch.npz \
  --density-column dn-dr --out results-unweighted --symlog
```

`r·VirX` трактуется как `dV/dr`, где `VirX = (dV/dr)/r`.
Это не производная второго столбца: `d(rV)/dr = V + r·dV/dr`.

Сравнение нескольких наборов с общим референсом:

```bash
python compare_many.py \
  --case fit-A EAMMOD1044 params-A.npz \
  --case fit-B EAMMOD1044 params-B.npz \
  --out comparison-fits --symlog
```

Для других классов укажите `--class EAMWMOD1046` или `--class EAMWMOD0644`
в `compare_mod.py`. Используйте соответствующий физическому потенциалу референс;
совпадение разных классов с одной таблицей не предполагается.
Другой каталог таблиц выбирается через `--reference DIR`.

## Что проверяется

По умолчанию backend `mdcraft` получает V и F из C++-методов, n — после
`Multi.charge` на двух атомах, производные — из отдельных силовых проб.
Пробные копии коэффициентов в памяти изолируют парный и embedding-вклады;
исходный файл не изменяется. Термостат, периодические образы, интегрирование
и MPI-декомпозиция не используются.

У `EAMMOD1044.value()` учтён множитель 2: этот метод возвращает V/2.
Для восстановления dF/dn нужна непостоянная плотность; вырожденная проба
завершится явной ошибкой. Атомные ядра пропускают r² < 1e-8, поэтому при
r < 1e-4 nm плотность и её производная берутся из независимой аналитической
формулы. Эти точки не являются проверкой C++-ядра. V при r=0 не запрашивается.
Вспомогательное `(dn/dr)/r` при r=0 записывается как NaN.

Внутренняя согласованность производных отдельно проверяется пятиточечными
конечными разностями. Backend `--backend formula` использует независимые
Python-формулы и **не проверяет исполнение C++**.

## Результаты

- `comparison.pdf` и шесть PNG: функции, ошибки и дополнительные произведения.
- `*_comparison.csv`: исходная сетка, референс, расчёт и ошибки.
- `*_all_quantities.csv`: дополнительные величины, включая r·dV/dr,
  d(rV)/dr, n·dn/dr, n·dF/dn и F·dF/dn. Независимых эталонных колонок для
  этих дополнительных произведений не предполагается.
- `summary.csv`, `report.json`: PASS/FAIL, RMSE, максимум абсолютной ошибки,
  относительная L2-ошибка и проверка производных.
- `reference_audit.json`: информационная проверка согласованности колонок.
- `overlay.png/pdf`: наложение шести основных кривых при нескольких наборах.

Критерий: `abs(calc-ref) <= atol + rtol*abs(ref)`, по умолчанию
`rtol=1e-3`, `atol=1e-6`. Все исходные точки участвуют в абсолютной проверке;
почти нулевые знаменатели исключаются только из относительной ошибки.
Границы `--r-min/--r-max`, `--n-min/--n-max` меняют только графики.
`--no-plots` отключает изображения. `--symlog` сохраняет отрицательные значения.

Код выхода 0 означает успешную проверку; 2 — несовпадение или провал проверки
производных с сохранёнными отчётами; 1 — ошибка выполнения. Ошибки аргументов
argparse также возвращают 2.

## Самопроверка

```bash
python self_test.py --backend formula
python self_test.py --backend mdcraft
# Только аудит ваших таблиц, без параметров и MDcraft:
python compare_mod.py --audit-only --out reference-audit
```

Самопроверка использует временные синтетические коэффициенты для всех трёх
классов. Они проверяют скрипты и согласованность производных, а не физический fit.
Локальные коэффициенты, референсные таблицы и результаты исключены через
`.gitignore`; не добавляйте их принудительно без намерения опубликовать.
